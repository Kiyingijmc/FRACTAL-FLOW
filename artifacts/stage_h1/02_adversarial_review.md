## 2. Negative Control & Mutation Demonstrations

1. **Negative Control for Open-Risk KPI:**
   - If `openRiskR` in `Header.tsx` is forced to `null`, the component displays `INVALID` in rose text and omits any numeric text.
   - If an included position is corrupted with negative risk (`allocatedRiskR = -0.5`), `evaluatePortfolioRisk` returns `status: 'INVALID'`, causing both desktop and mobile headers to render `INVALID`.
2. **Negative Control for Precision:**
   - If `evaluatePortfolioRisk` rounds each position to hundredths (`Math.round(0.005 * 100)`), the sum of three `0.005R` positions becomes `0.03R`, immediately failing `H1-RISK-02.1` (`result.totalRiskR === 0.015`).
3. **Negative Control for Cryptographic Conformance:**
   - If `sha256` truncates UTF-8 via `charCodeAt(i) & 0xff`, the Unicode test string `"FRACTAL-FLOW © 2026 \u00e9\u00e8\u00e0 \ud83d\udd12"` fails with mismatching digest, caught by `H1-CRYPTO-01.3`.
